# ADR 0001: Expo (CNG) or bare React Native

Status: accepted
Date: 2026-10-20
Decision: expo

> `Decision:` is `expo` or `bare`. `Status:` becomes `accepted` only after the user agrees.

## Context

Mini Mansion is a pixel-art point-and-click adventure (PRD v0.1.0, approved) built on the engine of the
"Minuit moins 13" POC (`midnight-mansion`, Expo SDK 57, accepted on the user's phone on 2026-10-19). The needs that
matter:

- **Rendering:** 24 scenes of 320x180 logical px scaled to the screen height with **nearest-neighbour** sampling,
  an animated walking hero (4 frames at 8 fps, 60 px/s along a path), 5 inhabitants with idle, talk and activity
  frames, 17 items. All art is drawn in code (pixel arrays + palettes). As in the POC: **`@shopify/react-native-skia`**
  turns pixel arrays into `SkImage`s once (`Skia.Image.MakeImage`) and draws them in one `<Canvas>` with
  `FilterMode.Nearest`; a JS game loop drives the walk (Reanimated is present because Skia needs it at runtime).
  Later versions will replace the provisional scenes with pixel art converted from the user's photos: they will
  still be pixel arrays or small PNGs drawn through the same Skia path, so this choice does not change.
- **UI over the canvas:** action menu, dialogue choices, inventory, notebook, digit keypad, **chess board overlay**
  (8x8 Views with highlights), banners and menus are plain React Native Views/Text; hotspots and exits are
  transparent `Pressable`s with `testID`s, so Maestro plays the walkthrough by IDs.
- **Engine:** pure TypeScript (state, character states, captures, puzzles, notebook, pathfinding, chess legal-move
  generator, save), tested with Jest, including the exhaustive state-graph search; no library.
- **Sound:** 8-bit effects and chiptune loops synthesized by a Node script into bundled WAV files, played with
  `expo-audio` + `expo-asset`; looping activity sounds (drums, typing, washing machine) need several concurrent
  players, which `expo-audio` supports; pause in background (`AppState`).
- **Languages:** French + English, phone language through `expo-localization`, per-language launcher name (factory
  overlay).
- **Display:** landscape lock, immersive fullscreen (config plugin from the POC).
- **Storage:** AsyncStorage (versioned autosave, settings, language, consent).
- **Telemetry:** opt-in Firebase Analytics + Crashlytics (React Native Firebase, config plugins).
- **No haptics, no sensors, no network, no custom native module.**
- **Build:** local Gradle on Windows, signed arm64 APK, sideloaded; no EAS, no cloud. APK target < 60 MB.

## Criteria

| Criterion | Weight | Expo (CNG + prebuild) | Bare React Native | Notes |
|---|---|---|---|---|
| All required libraries work with Expo prebuild / config plugins | high | yes | yes | Skia 2.6, Reanimated 4, expo-audio, expo-localization, AsyncStorage, RN Firebase: same set as the POC, proven on device |
| Need to hand-edit native Android code continuously | high | no | no | landscape + immersive mode + AD_ID removal are existing config plugins |
| Custom native module (Kotlin/C++) needed | medium | no | no | |
| Reuse of the POC engine and build setup | high | direct (same stack) | native config ported by hand | the POC is Expo SDK 57 |
| Upgrade effort over time | medium | low (bump SDK, `expo install --fix`) | high (Upgrade Helper merges) | all factory apps are on Expo SDK 57 |
| Build simplicity on this machine (local Gradle) | medium | `build-apk.mjs` prebuild + gradlew, proven on 5 apps | gradlew, proven by no app here | |
| Firebase setup effort | low | config plugins | manual Gradle setup | |

## Decision

**Expo (CNG, SDK 57, local prebuild)** with **Skia** for the scene and React Native Views for the UI, reusing the
POC's engine and rendering approach. Accepted by the user on 2026-10-20.

1. It is exactly the stack of the POC, already proven on the user's phone: the engine, the Skia pixel pipeline, the
   audio synthesis and the config plugins carry over without porting.
2. Every library the PRD needs works with Expo prebuild; none of the "choose bare" criteria applies.
3. Upgrades stay a version bump and the local build path is proven on five factory apps.

## Consequences

- Easy: one canvas per scene, sprites decoded once from code; UI, hotspots, keypads and the chess board stay ordinary
  React Native components with `testID`s; the whole game logic is pure TypeScript tested with Jest.
- Harder: Skia does not run in Jest; drawing stays thin and pixel-to-image conversion is a pure tested function;
  visual checks rely on Maestro screenshots. 24 scenes and 6 animated characters make the art data large: keep it
  in per-place modules and decode lazily per place if startup exceeds the 3 s cold-start budget.
- Hotspot overlays share one `sceneTransform` with the canvas (unit-tested with the 22x22 logical px minimum).
- Expo: `android/` is generated by `npx expo prebuild` and git-ignored; native changes go through config plugins.
- APK size is driven by Skia (~11 MB); target < 60 MB as for the POC (49.7 MB).

## Alternatives considered

- **Bare React Native:** same libraries, more upgrade work, the POC's config would have to be ported by hand; no
  benefit for this game.
- **Views + Reanimated only (no Skia):** Android bilinear image scaling blurs pixel art; drawing scenes from pixel
  arrays is not possible with Views.
- **expo-gl + three.js:** 3D-oriented and heavier; overkill for 2D sprites.
